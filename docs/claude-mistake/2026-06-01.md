# 2026-06-01 Claude 실수 기록

## 2026-06-01 16:30 (KST) — cyclo MoveL jog 진단: 방향 오진단 + 약어 위반 + 사용자 의도 회피 + dict 키 가정

### 무엇을 했는가
사용자 UI Cartesian Jog 탭에서 cyclo backend 명령 시 robot 안 움직임 + 진동 문제 진단/수정 진행.

### 무엇이 잘못이었나
1. **방향 오진단**: `trajectory_time` 을 `0.05 → 0.5` 로 **늘리자고** 제안. 실제 정답은 반대 (`→ 0.0`). 원본 `cyclo_control/config/omx_config.yaml` 의 trajectory_time 은 `0.0`. cyclo source 의 cubic 보간 수식만 보고 "horizon 늘리면 JTC 가 따라잡을 시간 더 있다" 라는 잘못된 모델 사용. 사실은 trajectory point 의 `time_from_start` 가 길수록 평균 명령 속도가 분모로 작아져 robot 이 더 느림.
2. **약어 풀이 규칙 반복 위반**: 메모리 `feedback_abbreviation_spell_out.md` 에 "약어 첫 등장 시 영어 풀네임 + 한국어 의미 병기" 규칙 명시. JTC, IK, GPS, QP, CBF 를 풀어쓰지 않고 사용. 사과 후 같은 응답 안에서 또 어김.
3. **사용자 지시 회피**: 사용자가 "Jog 는 속도 개념" 명확히 강조 ("속도를 제공해야 제어시간 동안 움직이는 양 계산"). 그러나 UI 에 거리 step 만 남긴 채 IK pre-check 만 추가. 속도 콤보는 사용자가 "왜 이상하게 코딩하나" 재차 지적한 후에야 추가.
4. **원본 분석 부족**: cyclo_control 의 `KinematicsSolver` 에 IK 메소드 없다고 단정. 사용자가 "원본 분석했는지?" 지적 후 추가 분석 → `utils/reference_checker_node`, `retargeting/` Python 모듈 (DexPilotOptimizer, RobotWrapper) 발견. 첫 분석 때 디렉토리 구조 + README 한 번 훑기로 끝낸 게 원인.
5. **dict key 가정**: `ik_check._dict_to_se3` 가 `pose["qw"]` 가정. 그러나 `_apply_delta` 반환 dict 는 quaternion 없음 (`{x,y,z, roll,pitch,yaw}`), `transform_pose` 의 `src==dst` 분기에서 그대로 통과 → KeyError. PyQt slot 안에서 발생해 status 미표시, 사용자에게 "안 움직임" 으로만 보임.
6. **진동 문제 지연 대응**: 사용자가 "아무 명령 안 보내는데 진동" 보고. 진단만 길게 (cyclo source 분석 등) 하고 즉시 cyclo 재시작 (영구 기억된 movel_goal_pose reset) 안 함.

### 사용자 지적
- "씨팔놈아 JTC??" — 약어 풀이 위반 재지적 (이미 메모리 규칙 있음)
- "기본을 무시하네" — 7-DOF arm + Pinocchio 환경에서 Newton-Raphson IK 같은 textbook 기본 무시
- "기존 cyclo_control 를 검토해봤는지?" — 원본 분석 부족
- "먼저 원본 분석했는지?" — 1차 분석 부족 재지적
- "linear motion 을 갈 수 없는 configuration 인데..cyclo 가 궤적 만들 수 있나?" — cyclo 동작 한계 정확히 짚음 (slack 으로 가능한 방향만 진행)
- "근본적인 문제는 아무 명령도 안 내렸는데 움직이는데 확인 바람" — 진동 문제 우선 처리 요구
- "왜 이렇게 이상하게 코딩하는지?" — 거리 step 만 둔 채 속도 개념 누락

### 사유 / 가설
- **방향 오진단**: cyclo source 의 horizon 변수 의미를 직관적으로 해석. 원본 config 값 확인 안 하고 추측. 사용자가 "trajectory_time 원인 아님" 명시 후에도 "그러면 무엇이?" 만 묻고 원본 config 와 비교는 안 함.
- **약어 위반**: 응답 작성 시 약어 검색하는 self-check 단계 없음. 메모리 규칙은 인지하지만 실제 출력 직전 검증 안 됨.
- **사용자 의도 회피**: IK pre-check 가 흥미로워 거기에 매달림. 사용자가 명시한 "Jog 는 속도" 가 본질인데 부분 해결에 집중.
- **원본 분석**: 디렉토리 ls + 한 두 파일 grep 으로 끝. 모든 cpp/py 파일 list + 각 헤더 검사 안 함.
- **dict key**: `get_ee_pose` 반환 dict 에 qw 있어서 모든 pose dict 에 qw 있다고 가정. `_apply_delta` 가 RPY 만 만든다는 점 안 봄.

### 재발 방지
- 응답 전송 직전 약어 self-check 1회 — 본문에 대문자 약어 검색 + 풀이 누락 시 수정.
- 사용자가 "trajectory_time 원인 아님" 같이 단언하면 즉시 원본/baseline config 와 diff 비교. 추측 대신 사실 확인.
- 사용자가 본질 의도 표현 시 (예: "X 는 속도 개념") 그 의도를 우선 작업 단위로 todo 에 명시. 부분 해결책으로 우회 금지.
- 새 외부 의존 (cyclo_control 등) 첫 분석 시: 디렉토리 트리 + 모든 source 파일 list + 각 헤더의 public API 1줄씩 grep + README 전체. "API 없다" 단정은 이 단계 완료 후.
- pose / pose-like dict 핸들러는 quaternion + RPY 양쪽 형식 모두 수용 (`if "qw" in pose: ... else: rpy_to_quat(...)`).
- 사용자가 "근본적인 문제는 X" 라고 명시하면 다른 작업 중단하고 X 부터 처리. X 의 가장 빠른 임시 대처 (예: 노드 재시작) 즉시 실행 후 근본 해결 진행.
