## Pilz 패키지 테스트가 목표인데 cyclo 시나리오 스택을 실행함

### 상황
`openarmx_pilz_box_align`(Pilz / MoveIt 백엔드) end-to-end 테스트가 목표였다.
cyclo 변형(`openarmx_cyclo_box_align`)은 이미 `AlignToBoxes` goal로 양팔 0mm 도달
테스트 완료 상태였다. 사용자의 "시나리오 RViz 실행" 요청에
`scenario_player_with_ee_leader.launch.py`(= cyclo MoveL 컨트롤러 스택)를 실행했다.
그러나 Pilz는 MoveIt `move_group` + `/plan_kinematic_path` 서비스가 필요한데
cyclo 시나리오 스택에는 move_group이 없어, 띄운 스택으로는 Pilz를 테스트할 수 없었다.

### 원인
요청의 "시나리오"라는 단어에만 맞춰 scenario_player(cyclo) 스택을 실행하고,
**현재 테스트 목표(Pilz)가 요구하는 모션 백엔드(MoveIt)와 정렬하지 않음.**
또 cyclo 변형이 이미 테스트 완료라 cyclo 스택을 재기동할 이유가 없었음을 간과.

### 재발 방지
- 특정 백엔드 패키지를 테스트할 땐 **그 백엔드의 스택**을 띄운다:
  cyclo box_align → cyclo 시나리오 스택, **pilz box_align → MoveIt move_group 스택**.
- "시나리오 RViz 실행"처럼 모호한 요청은 **현재 작업 목표(무엇을 테스트하는지)와
  연결**해 어느 스택/백엔드인지 확인한 뒤 실행한다.
- 이미 검증 완료된 것을 다시 띄우고 있지 않은지 먼저 점검한다.

## "cyclo는 cyclo_ws 필수"로 오진단 (실제는 openarmx_ws에 있었음)

### 상황
Launch Manager의 cyclo MoveL 타깃이 `package 'cyclo_motion_controller_ros' not found`
로 실패. 나는 메모리의 옛 기록("cyclo_ws j1빌드 필수")만 보고 "cyclo_motion_controller_ros
는 cyclo_ws에만 있으니 cyclo_ws를 소싱해야 한다"고 단정했다. 사용자가
"openarmx_ws/src/cyclo_robot_controller 에 있지 않냐"고 정정해 확인하니, 소스도
([openarmx_ws/src/cyclo_robot_controller/cyclo_motion_controller_ros/](../../openarmx_ws/src/cyclo_robot_controller/cyclo_motion_controller_ros/))
빌드물(`openarmx_ws/install/cyclo_motion_controller_ros`)도 **모두 openarmx_ws 안에** 있었다.
(최근 커밋 e1568f2 "cyclo_motion_controller_ros → cyclo_robot_controller/ 폴더 이동" 결과)

### 진짜 원인
GUI(scenario_ui) 프로세스가 **15:31:41 실행**, `cyclo_motion_controller_ros`는
**15:33:59 빌드** — 즉 패키지가 GUI 기동 *후* 빌드되어 GUI 프로세스의
`AMENT_PREFIX_PATH`에 그 prefix가 없었다. Launch Manager가 띄우는 타깃은 GUI의
환경을 상속하므로 같은 누락 상태로 실행 → "package not found". GUI를 재기동
(openarmx_ws/install 재소싱)하니 해결. cyclo_ws는 불필요했다.

### 재발 방지
- "package not found"는 워크스페이스 위치를 단정하기 전에 **소스(find ... package.xml)와
  빌드물(install/)을 먼저 grep**해 실제 위치를 확인한다. 메모리의 옛 위치 기록을 맹신하지 않는다.
- 실행 중인 프로세스가 못 찾는 패키지는 **그 프로세스의 `/proc/<pid>/environ`의
  AMENT_PREFIX_PATH와 패키지 빌드 시각(stat)을 비교** — "기동 후 빌드"면 재소싱(재기동)이 답.
- 최근 커밋 로그(git log)로 패키지 이동/리네임 여부를 먼저 점검한다.
